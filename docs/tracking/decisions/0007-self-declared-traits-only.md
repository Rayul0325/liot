# 0007. 거주자 특성은 본인·보호자의 직접 입력과 동의로만 받고 추론하지 않는다

- 날짜: 2026-10-19
- 상태: 채택

## 맥락

취약 거주자 가산에는 나이·대피 능력·인지 상태·혼자 사는지가 필요하다. 이 중 건강 관련 정보는 개인정보보호법 제23조의 민감정보다. 센서 데이터(움직임 패턴 등)로 추정할 수도 있지만, 추정 결과도 민감정보 생성이 된다.

## 결정

- 특성은 정확히 넷(75세 이상, 혼자 대피 어려움, 인지 저하, 혼자 산다)이고 모두 예/아니오다. 생년월일·진단명은 받지 않는다. 대피는 "혼자 대피할 수 있나요?" 기능 질문으로 받는다.
- 직접 입력 + 명시 동의로만 생긴다. 센서나 모델로 추론해 저장하지 않는다.
- 이 기기 DB 에만 둔다. ntfy·외부 LLM·결정 모델 입력·로그 어디에도 넣지 않는다. 가산은 결정론으로만 한다.
- 인지 저하는 보호자만 입력한다. 사람 단위로 저장하고, 삭제하면 값을 지운다.
- 재실 여부와 무관하게 적용한다.

## 대안

- 센서로 추론(예: 오래 움직임 없음 → 취약): 민감정보를 동의 없이 만든다. 기각. ('오래 움직임 없음'은 상황 감지로만 다룬다.)
- 생년월일을 받아 나이 계산: 필요한 것은 75세 이상 여부 하나다. 원자료를 저장할 이유가 없다. 기각.
- 재실 중일 때만 가산: 재실 감지는 믿기 어렵고, 놓치면 취약 거주자 집의 경보가 약해진다. 기각.
- 특성을 모델에 넣어 판단 품질을 높인다: 외부 송신 경로가 하나 늘고, 모델이 특성을 근거로 낮추는 길이 생긴다. 기각.

## 결과

- 계약 모델(판단·제안·알림)에 특성 필드가 없다. 판단 경로로는 '취약 거주자가 있는가' 불리언만 간다.
- 과거 판단에는 '거주자 가산 적용됨'(출처 resident)만 남는다.
- 거주자가 입력하지 않으면 가산이 없다(놓침을 감수한 선택).
- 영유아·반려동물 특성은 지금 없다.
