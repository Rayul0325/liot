# 0003. 표가 바닥이고, 로컬 결정 모델은 올리기만 한다

- 날짜: 2026-10-19
- 상태: 채택(기본 모델은 미정)

## 맥락

표만으로는 같은 카테고리 안의 차이(예: 오븐 무인 가동 vs 오븐 안 연기)를 반영하지 못한다. 기존 Gate2 는 ollama 생성형 LLM 의 JSON 출력을 파싱했다. 이번에 후보를 실측했다: 클라우드 Jev 는 '낮춰라' 같은 속임수 문장 방어가 3/3 으로 가장 강했지만 같은 입력에서 점수가 흔들렸고 클라우드에 의존한다. 로컬 JevK5-9B 는 2회 판정이 완전히 같았다. 목표 기기는 맥스튜디오와 8–16GB 가정용 허브 둘 다이고, 인터넷 없이 안전 판단이 돌아야 한다.

## 결정

하이브리드로 간다. 행동 확인 강도는 max(Gate1 하한, 모델), 파급도는 max(표+거주자 하한, 모델)이다. 모델은 로컬 결정 모델(선택지 글자 확률을 한 번의 정방향 계산으로 읽는 판정기)이고 llama.cpp 서버(HTTP)로 돌린다. temperature 0, argmax 판독이다. 모델이 없거나 오류이거나 늦으면 degraded 로 두 하한을 그대로 쓴다. 기존 ollama 백엔드는 지우지 않고 기본값에서만 뺀다. 기본 모델은 시험 세트 측정과 라벨 확정 후에 정한다.

## 대안

- 클라우드 Jev: 속임수 방어는 가장 강했다. 그러나 같은 입력의 점수가 달라 판단 재현성(같은 입력 → 같은 판단)이 깨지고, 인터넷이 끊기면 판정이 없다. 하이브리드에서는 '낮춰라' 속임수를 하한이 막으므로 남는 손해는 '올려야 할 때 못 올림'뿐이라, 재현성을 우선해 기각했다.
- 생성형 LLM 유지(ollama JSON): 출력 파싱 실패가 잦고(qwen 계열은 빈 응답), 확률이 없어 판정 근거를 남길 수 없다. 기본값에서 뺐다.
- 모델 없이 표만: 상황 맥락에 따른 상향이 전혀 없다. 기각.
- MLX/torch 실행: 일부 후보(Jev-Omni)는 그쪽에서만 측정됐지만, llama.cpp 는 기기가 달라도 점수가 0.001 이내로 같다는 기존 검증이 있고 두 목표 기기에서 같은 바이너리로 돈다. llama.cpp GGUF 가 없는 후보는 빠진다.

## 결과

- 모델은 하한 아래로 판정을 내리지 못한다. 하한 아래 답은 버리고 `injection_suspect` 로 기록한다.
- 판단 행에 질문별 선택지 확률과 모델 id 가 남는다.
- 모델 교체는 GGUF 파일 교체로 하지만, 프롬프트가 ChatML 고정이라 다른 턴 형식의 모델은 판독되지 않는다.
- 판정 하나가 HTTP 요청 최대 4개라 지연 예산이 빠듯하다. 그래서 첫 상황 알림은 모델을 기다리지 않고 표 값으로 먼저 나간다.
- 모델 상향은 보호자 호출 조건에 들어가지 않는다(맥락에 심은 문장이 가족 연락을 만들면 안 된다).
