# 0006. 상황 알림은 표 값으로 먼저 보내고, 모델 판정은 그 뒤에 돈다

- 날짜: 2026-10-19
- 상태: 채택

## 맥락

결정 모델 판정은 질문 둘 × HTTP 두 번이고, 측정에서 두 질문 합계 p95 가 1초를 넘었다. 판정을 기다린 뒤 알림을 보내면 가스 알림이 그만큼 늦고, 모델 서버가 멈추면 제한시간만큼 더 늦는다. 기존 동작은 안전 신호가 즉시 불씨 제안을 만드는 것이었다(Safety-Never-Silent).

## 결정

상황 알림만 두 단계로 보낸다.

1. Gate1 하한과 파급도 하한만으로 제안을 만들어 즉시 보낸다(모델 호출 없음). 이 판단 행은 모델 id `pending-decision-model`, 평결 `pending` 으로 남긴다.
2. 모델 판정을 이벤트 루프를 막지 않는 별도 스레드에서, 추적되는 백그라운드 태스크로 돌린다. 판단 행은 늘 남긴다. 위험도나 파급도를 올렸고 상황이 아직 열려 있으면 같은 상황 id 의 후속 제안을 보낸다.

컴포트 제안은 판정 후 발송 그대로다.

## 대안

- 판정 후 발송(기존 방식 유지): 첫 알림이 모델 지연만큼 늦다. 기각.
- 판정 결과를 기다리되 짧은 제한시간: 제한시간이 곧 알림 지연이다. 기각.
- 2단계를 `await` 로 기다린 뒤 반환: 스트림의 다음 신호(가스 직후 연기)가 앞 상황의 모델 판정 뒤에 줄 선다. 실제로 이 문제가 있어 백그라운드 태스크로 고쳤다.

## 결과

- 상황 하나에 알림이 두 번(첫 알림 + 상향 후속) 갈 수 있다.
- 2단계가 끝나기 전에 상황이 닫히면 후속은 보내지 않는다(낡은 경보 방지). 판단 행은 남는다.
- 테스트는 `drain_phase2()` 로 2단계 끝을 기다려야 하고, DB 를 닫기 전에 drain 해야 한다.
- 마감을 넘긴 판정 스레드는 취소되지 않고 요청당 제한시간까지 돈다.
