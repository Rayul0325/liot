# 0010. 관제실은 데몬 DB 를 공유하고, 로그인 없이 입력자 표시로만 구분한다

- 날짜: 2026-10-19
- 상태: 채택(로그인은 이후 범위)

## 맥락

거주자·특성·보호자·동의를 입력할 화면이 필요했다. 기존 관제실 데모 서버는 요청마다 메모리 앱을 새로 만들어 상태가 남지 않는다. 데몬은 별도 프로세스다. 인증 체계를 이번에 만들 여유가 없었다.

## 결정

- 관제실의 안전 설정 API 는 요청마다 데몬과 같은 SQLite 파일(`LIOT_DB_PATH`, 기본값은 데몬과 한 곳에서 정의)을 열어 쓰고 닫는다. 데몬은 매 상황·매 전달 시점에 DB 에서 읽으므로 재시작 없이 반영된다.
- 로그인은 없다. 접근은 이 기기(루프백)·이 기기 Host·이 기기 Origin·JSON 본문으로만 제한한다.
- '인지 저하는 보호자만 입력'은 입력자(`resident`·`guardian`) 표시·기록으로만 지킨다.

## 대안

- 관제실이 데몬 HTTP API 를 거친다: 데몬에 새 쓰기 표면이 생기고, 그 표면은 외부 노출 가능성이 있는 피드백 수신구와 같은 프로세스다. 기각.
- 지금 로그인을 만든다: 계정·세션·복구까지 범위가 커진다. 이후 범위로 미뤘다.
- 별도 DB: 입력한 값이 데몬에 안 보이는 일이 생긴다. 기각.

## 결과

- 이 기기 화면을 쓸 수 있는 사람은 누구나 입력자를 '보호자'로 골라 어떤 특성이든 입력할 수 있다.
- 두 프로세스가 같은 파일을 쓰므로 WAL 모드가 전제다. 둘이 다른 작업 디렉터리에서 기본 상대 경로를 쓰면 서로 다른 파일을 보게 된다.
- 보호자 비밀 토픽은 등록 응답에 한 번만 보인다. 다시 보는 화면이 없다.
