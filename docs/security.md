# 보안·개인정보 정책

## 지키는 자산

| 자산 | 왜 민감한가 | 어디에만 있나 |
|---|---|---|
| 거주자 특성(75세 이상·혼자 대피 어려움·인지 저하·혼자 산다) | 건강 관련 정보는 개인정보보호법 제23조의 민감정보다 | 이 기기 SQLite 의 거주자·특성·집 설정 테이블 |
| 보호자 비밀 토픽 | 아는 사람은 누구나 그 보호자에게 알림을 보내거나 엿들을 수 있다 | SQLite 보호자 테이블. 등록 응답에 한 번만 보인다 |
| 서명 비밀키(`LIOT_NOTIFY_SECRET`) | 이 키로 수락·거절·확인 링크를 위조할 수 있다 | 데몬 프로세스 환경변수 |
| HA 장기 액세스 토큰(`LIOT_HA_TOKEN`) | 집 전체 상태를 읽고 기기를 조작할 수 있다 | 데몬 프로세스 환경변수 |
| ntfy 인증 토큰(`LIOT_NTFY_TOKEN`) | 보호된 토픽에 쓸 수 있다 | 데몬 프로세스 환경변수 |
| 1회용 링크 토큰(nonce) | 링크 재생으로 이중 확인을 채울 수 있다 | 데몬 메모리(재시작하면 사라진다) |
| 기기·방 이름, 판단 근거 문장 | 집 구조와 생활 패턴이 드러난다 | DB 안. 외부로 나가지 않는다 |

## 인증 흐름

### 거주자 피드백 링크(`GET /feedback`)

1. 알림을 보낼 때 제안마다 1회용 nonce 를 새로 발급한다. 버튼 링크의 서명 대상은 `제안id:티어정수:행동:nonce` 의 HMAC-SHA256 이다. 행동(수락·거절·미루기·괜찮아요)마다 서명이 따로라 한 버튼으로 다른 응답을 할 수 없다.
2. 수신구는 다음 순서로 검사하고, 처음 걸린 곳에서 거부한다.

| 단계 | 실패 조건 | 응답 |
|---|---|---|
| 요청 줄 | GET 이 아님 | 405 |
| 요청 줄 | 5초 안에 줄이 오지 않음·형식 오류 | 400 |
| 경로 | `/feedback`·`/guardian-ack` 밖 | 404 |
| nonce | 이 제안에 살아 있는 nonce 가 없거나 다름(이미 쓴 링크, 재시작 전 링크 포함) | 403 `stale or already-used link` |
| 제안 | 이 집에 그 제안이 없음 | 404 |
| 수명 | pending 이 아니고 이중 확인 대기도 아님, 또는 이중 확인 링크의 상한(제안 만료 시각, 발급 후 15분) 초과 | 403 `expired link`. 단 만료된 상황 제안의 링크는 서명이 맞으면 사다리만 멈추고 200 |
| 서명·행동 | 모르는 행동이거나 서명이 맞지 않음 | 403 `invalid signature or action` |

3. 통과하면 상태를 옮기고, 그 제안이 상황 제안이면 사다리를 멈추고, nonce 를 소비한다. 미루기(제안이 pending 으로 남는 응답)와 '괜찮아요'는 nonce 를 소비하지 않는다 — 사람 손에 다른 링크가 없기 때문이다.
4. 비-ASCII 서명·nonce 는 예외가 아니라 불일치로 처리한다(500 과 403 의 차이가 nonce 존재 신호가 되지 않게).

### 보호자 확인 링크(`GET /guardian-ack`)

- 서명 대상은 `guardian-ack:상황id:보호자id` 다. 보호자마다 서명이 달라 `g=` 만 바꿔 다른 보호자인 척할 수 없다. nonce 는 없다 — 확인은 멱등이다.
- 거부 순서: 서명 불일치 403 → 사다리가 없거나 다른 집 404 → 그 보호자에게 전달된 적 없음 403 → 지금 동의가 유효하지 않음 403. 이미 멈춘 사다리는 200 `already acknowledged`.
- 알림을 여는 것(Click)은 확인이 아니다. 확인은 별도 버튼으로만 한다.

### 되돌리기(`GET /feedback?a=undo`)

- 서명 대상은 `제안id:티어:undo:` (nonce 없음)다. 되돌리기 링크는 알림에 실리지 않아 비밀키를 가진 쪽만 만들 수 있고, 성공하면 저장해 둔 이전 상태를 지워 1회용이 된다.
- 실행기가 없으면 404, 서명이 틀리면 403, 되돌릴 이전 상태가 없으면 404 다.
- 현재 결함: 탭 한 번으로 실행한 밸브 잠그기·도어락 잠그기를 되돌리면 HA 에 밸브 열기·도어락 풀기가 나간다. 서명 키를 가진 쪽은 누구나 이 요청을 만들 수 있으므로, 고칠 때까지 실행 옵트인을 켜지 않는다.

### 개발 키 차단

`LIOT_NOTIFY_SECRET` 이 비었거나 공백이면 소스에 공개된 개발 키가 쓰인다. 그 동안 데몬은 **피드백 수신구를 열지 않는다**. 바인드 주소로 안전을 추정하지 않는다 — 앞단 프록시·터널은 프로세스 안에서 보이지 않는다. 로컬 확인용으로만 `LIOT_FEEDBACK_ALLOW_DEV_KEY=1` 로 명시해 열 수 있다.

### 관제실 안전 설정 API(`/api/safety/*`)

로그인이 없다. 대신 다음을 모두 만족해야 한다.

| 조건 | 실패 시 |
|---|---|
| 접속 주소가 루프백(이 기기) | 403 |
| `Host` 가 `localhost` 또는 루프백 IP(DNS 리바인딩 차단) | 403 |
| 쓰기(POST): `Origin` 이 있으면 이 기기 이름, `Content-Type` 이 JSON | 403 |

`LIOT_LAB_HOST=0.0.0.0` 으로 띄워도 다른 기기에서는 안전 설정 API 가 열리지 않는다. 실험실 API(`/api/simulate` 등)는 이 검사를 받지 않는다 — 거주자 정보를 다루지 않기 때문이다.

## 권한 표

| 주체 | 할 수 있는 일 | 조건 | 할 수 없는 일 |
|---|---|---|---|
| 그 집 거주자(관제실) | 거주자 등록·삭제, 75세 이상·혼자 대피 답 입력, 혼자 산다 설정, 집 별칭, 보호자 등록·비활성화, 동의 부여·철회 | 이 기기 브라우저. 동의 조작은 등록된 그 집 거주자 id 로만 | 인지 저하 입력(입력자 '거주자'로는 거부), 다른 집 거주자·보호자 조작, 생년월일·진단명 입력 |
| 보호자(관제실 입력자 표시) | 75세 이상·혼자 대피·인지 저하 입력 | 입력자로 '보호자'를 고름 | 동의 부여·철회(거주자만), 혼자 산다 입력 |
| 거주자(폰) | 제안 수락·거절·미루기·괜찮아요, 사다리 확인 | 서명이 맞고 nonce 가 살아 있음 | 쓴 링크 재사용, 한 버튼으로 다른 응답 |
| 보호자(폰) | 전달받은 상황의 사다리 확인 | 전달받았고 지금도 동의 유효 | 전달받지 않은 상황 확인, 철회 뒤 확인, 제안 상태 변경 |
| 결정 모델·LLM | 위험도·파급도 상향 제안 | — | 하한 아래로 낮추기(무시되고 기록), 보호자 호출(모델 상향은 보호자 조건에 들어가지 않는다) |
| 자연어 지시·선호 학습 | 컴포트 후보 억제·순위 조정 | — | 안전 카테고리·불씨·위험 파급도 억제 |
| 실행기 | 화이트리스트 행동 실행 | 실행 옵트인 + HA 연결 + 티어 권한(안전은 사람 승인) | 도어락 열기·밸브 열기, 안전 카테고리 자동 실행 |
| 누구도 | — | — | 119 자동 신고, 특성 추론 저장 |

'보호자만 입력'은 입력자 표시로만 지켜진다. 이 기기 화면을 쓸 수 있는 사람은 누구나 입력자를 '보호자'로 골라 인지 저하를 입력할 수 있다.

## 감사 기록

기록되는 것:

| 사건 | 어디에 |
|---|---|
| 제안 생성, 제안 상태 전이(수락·거절·만료 등), 피드백 | `audit_log`(덧붙이기만), `feedback` |
| 파급도 표 로드 실패(fail-closed 로 도는 중) | `audit_log` 한 번(`severity_table_load_failed`) + 경고 로그 |
| 모든 판단(1단계 pending, 2단계 concur·escalated·injection_suspect·degraded_fail_safe, 컴포트·억제된 능동 판단 포함) | `judgments` 한 판단당 한 행. 모델 확률·모델 id·출처 포함 |
| 거주자 알림 송신(정제된 키만) | `notifications` |
| 동의 부여·철회(시각·거주자 id) | `consent_events` — 갱신·삭제는 DB 트리거가 거부한다 |
| 보호자 전달·보호자 해소 알림·119 안내 | `guardian_forwards` |
| 사다리 확인 주체·시각 | `escalation_ladders.acked_by`·`acked_at` (`resident` 또는 `guardian:<id>`) |

기록되지 않는 것(현재 상태): 특성 입력·수정의 이력(최신 값과 입력자·시각만 남는다), 거주자 삭제, 보호자 등록·비활성화, 집 별칭 변경, 관제실 접속. 보호자에게 보낸 요약 알림 본문은 `notifications` 에 남기지 않는다.

## 자격 증명 수명

| 자격 증명 | 생성 | 저장 | 수명·폐기 | 교체 |
|---|---|---|---|---|
| 서명 비밀키 | 운영자가 임의의 긴 값을 만든다 | 프로세스 환경변수만. 저장소 금지(비밀 스캔이 막는다) | 프로세스 수명 | 바꾸고 재시작하면 나가 있는 모든 거주자 링크·보호자 확인 링크가 무효가 된다. 교체 기능은 따로 없다 |
| HA 토큰 | HA 설정에서 발급 | 환경변수만. 로그·예외 메시지에 싣지 않는다 | HA 쪽에서 폐기 | HA 에서 재발급 후 재시작 |
| ntfy 토큰 | ntfy 서버 | 환경변수만. 헤더에만 쓴다 | ntfy 쪽에서 폐기 | 재발급 후 재시작. 거주자·보호자 토픽 모두 같은 토큰으로 쓴다 |
| 보호자 토픽 | 등록 시 무작위 32바이트(url-safe) | DB 만. 목록·이력 응답·객체 표현에 넣지 않는다 | 보호자 비활성화로 전달 중단(행은 남는다) | 비활성화 후 새로 등록 |
| nonce | 발송마다 무작위 16바이트 | 메모리 | 소비·만료·재시작으로 사라진다. 이중 확인 링크는 발급 후 15분 | — |

## 민감정보 처리

- 특성은 직접 입력과 동의로만 생긴다. 센서·모델이 추론해 저장하는 경로가 없다. 화면에는 "이 기기 안에만 저장되고 밖으로 보내지 않는다"는 안내가 있다.
- 가산 계산은 '취약 거주자가 있는가' 불리언 하나만 판단 경로로 넘긴다. 특성 자체는 판단·제안·알림·모델 입력 어디에도 실리지 않는다.
- 거주자 삭제는 특성 행을 지운 뒤 secure_delete 로 빈 페이지를 0 으로 덮고 WAL 을 체크포인트한다. 동의 기록의 거주자 id 는 남는다(익명 id).
- ntfy 로는 허용 키만 나간다. 결정 모델·LLM 입력은 가명화되고, entity_id 꼴 문자열이 남으면 송신을 거부하고 degraded 로 떨어진다. 남은 PII 패턴(전화·이메일·주민번호·정밀 좌표)이 있으면 어느 목적지든 송신을 거부한다.
- 보호자 토픽은 로그에 쓰지 않는다. 송신 실패 로그에도 예외 종류만 남긴다. 단, aiosqlite 로거를 DEBUG 로 켜면 SQL 인자가 찍혀 보호자 등록 시 토픽이 로그에 나온다 — 운영에서는 그 로거를 DEBUG 로 두지 않는다.
- `.env`·DB 파일은 git 에서 제외된다. `make check` 의 비밀 스캔이 HA·ntfy·서명 키 환경변수에 값이 박힌 줄, 흔한 제공자 키, 개인키 블록을 막는다. 문서에 예시를 쓸 때는 `***` 나 `<...>` 를 쓴다.
