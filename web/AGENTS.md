# web

## Scope

Static browser UI served by `liot.demo_server` (no build step, plain JS):

- `app.html` + `assets/app.js` + `assets/app.css` — the pipeline lab: board of sensors/devices from `GET /api/catalog`, presets, registration forms, `POST /api/simulate` trace view (trigger, two lines, embedding, arbiter, Gate1, Gate2, judgment with severity and sources, proposal, intervention), phone-feedback simulation (`/api/feedback`), directive chat (`/api/directive`).
- `safety.html` + `assets/safety.js` — home and guardian settings: home alias and lives-alone, residents and their yes/no answers with "who is entering", guardian registration (secret topic shown once), consent grant/revoke by a chosen resident, consent history, forwarding history. Talks only to `/api/safety/*`.
- `home3d.html` + `assets/home3d.js` + `assets/home3d.css` — 3D virtual home (three.js, hand-written pointer rotation, 2D floor-plan fallback when WebGL or the module fails) with resident and guardian phones and a playback timeline. Talks only to `GET /api/catalog` and `POST /api/home3d/scenario`; every title, body, priority, button label and time it shows comes from that response.
- `day.html` + `assets/day.js` + `assets/day.css` — simulated days on the real `LiotService` (`/api/day/*`): day tabs, virtual clock and weather line, a vertical timeline of server `line_ko` lines, the resident phone (red safety card on top with the real ntfy title/body from the send record, proposal cards with [도움됐어요]·[무시]·[그만해] and the server `state_ko`, a 모아보기 tray for DIGEST items), per-day metrics, a 3-day comparison table and '속 보기' (rule, matched/skipped rules, score vs NoOp, candidates, tier, gate decision). A [가짜 모델 · 실제 모델] toggle sends `models` on run; the key status "키 n/4개" comes from `GET /api/day/keys` (names and presence only, in the tooltip). Cloud runs add: the reason writer under each reason ("작성 <model>" or "문장 틀 · <reason_fallback_ko>"), '속 보기' rows for 이유 작성·거주자 결정·참고한 기억 and Jev vs luna probability bars per question with the server's 일치/불일치 and served Jev model (`judge` events), a '기억' panel of `memory` events (source memgineering · liot-demo, 규칙/실패 badges), per-day 외부 호출·평균 지연·추정 비용 from `usage_day`, and the `models.fallback` line. Every decision value — probabilities, percentages, 일치/불일치, fallback reasons, states, metrics, usage strings, line_ko — comes from the server; bar widths are the server probabilities. Small display labels around those values are written by `day.js` itself (none of them is a decision): the cloud ones are "작성 ", "문장 틀", "키 n/m개" (from the server's present/total counts), the key-name suffixes " 있음"/" 없음" and "키 상태를 읽지 못했어요", the judge header prefixes "Jev "/"luna " with "비교함" or "미접근" (or the server's `luna_reason_ko`), "외부 호출"·"평균 지연"·"추정 비용", the "규칙"·"실패" badges, "참고한 기억", "거주자 결정", "이유 작성", and the empty-memory sentence "아직 기억을 찾거나 남기지 않았어요."; the static texts in `day.html` ("모델", "가짜 모델"·"실제 모델", the cloud note, "기억", "memgineering · liot-demo") are also the page's own. The plan-A labels (status words, table headers, button labels, "다음 단계에 반영돼요", "무시함 — 그대로 두면 만료돼요", inspect row names) were already page text. Streams with `EventSource` from `lastSeq + 1` and reconnects from there; viewer taps POST `/api/day/feedback` and show "다음 단계에 반영돼요" until the `feedback` event arrives; [무시] sends nothing. Tokens are a copy of the home3d `:root` block.
- `assets/day-demo.js` + `assets/day-demo.css` — the [시연 모드] overlay on `day.html` (`#demo`). [시연 모드] only opens the full-screen overlay — it never starts a run (`day.js` `onDemo`). A new `trace: true`, `pace_ms: 0` run starts only from the overlay's [새로 돌리기] (disabled while a run is live), so a cloud demo is never re-billed by reopening. Esc and [나가기] close the overlay; the run keeps going and reopening resumes the remaining queue. Closing mid-trace does not pause it: the current trace finishes while hidden (its cards still land in the pane) and the next one waits in the queue; [처음부터 다시 보기] replays it if it was missed (browser-checked 2026-10-20 with synthetic traces: closed on the first node of pA → pA's card applied while hidden, pB still queued; reopen played pB; replay restarted at pA). [처음부터 다시 보기] replays this run's received traces from the first one without any request. If a run without trace is live, [시연 모드] does not open and shows "시연 기록이 꺼진 실행이에요 — 끝난 뒤 시연 모드로 새로 돌려 주세요" on the page. Each new run or replay bumps a playback generation (`D.gen`); a `play()` still in flight stops at its next wait, so no stale card lands in the cleared pane. `day.js` forwards every `trace` event to `LiotDemo.push`; the player plays the queue in arrival order, one trace at a time: each node is highlighted for `max(real_ms, speed minimum)` (느리게 1500 · 보통 800 · 빠르게 300 ms — screen-only delay, the server is never slowed), split into three equal steps — ① the node's exits and score fan appear (hidden until then), ② the taken branch lights, ③ the next main edge and its pill light — then marked done/end/skipped from the server `state` (under reduced motion the three steps happen at once and there is no `dm-anim`; the final frame equals the static `render(t, true)` drawing); [건너뛰기] finishes the current trace; "대기 n건" is the queue length. The graph is SVG built with `createElementNS` only (`SVG_NS` is the one allowed `http://` string), arrowheads are small `path` triangles (no `marker`/`url(`), node coordinates come from fixed tables per kind (comfort · safety · followup · feedback) and ids the table does not know are not drawn. Node labels, times, edge pills, branch chips and outcomes are the server's `label_ko`/`real_ms`/`edge_ko`/`branches`/`outcome_ko`; a node's `detail_ko` is in its SVG `<title>` and in the caption ("label — detail · taken branch → edge_ko"). The page's own text is "실제 …ms", "시연 …초", the speed and button labels, "대기 n건", "첫 사건을 기다려요.", "거주자 폰", the "n일차" divider, the lane names ("침묵", "따라가는 알림 없음 · 사다리는 계속", "반영되지 않음", and "기록 없음" when the taken branch is `unknown` — never a claim the server did not make), and the sink fallbacks "모아보기"/"보류" when the server sent no branch for them (a skipped gate). The resident phone pane shows the current day's cards only: a trace from a new day clears it and puts "n일차" on top; whichever card a trace touches (created, followup line, feedback/ack line) moves to the top and the pane scrolls to the top, so the newest card is visible without scrolling at 1280×800. Cards reuse `.notif`/`.alarm` with the server's proposal/alert records (`window.LiotDay.proposal`/`alert`). At ≤ 640px the graph becomes one column: each node's branch chips sit to its right (x 170–366, the same branch set as the wide view, taken chip lit; followup `sent` is a chip there because there is no pane link), edge pills sit between rows, and every chip/pill box is drawn, measured and its foreignObject set to that height before the next row is placed; the phone pane moves below the graph (`#demoPane`); the overlay body scrolls vertically and nothing scrolls horizontally at 390px. There the overlay body jumps (no smooth scrolling) to keep the current node in view and to the phone pane when a card appears; with `prefers-reduced-motion: reduce` it does not auto-scroll. Animation classes (`dm-anim`) are applied only when `prefers-reduced-motion` is not `reduce`.
- `assets/vendor/three.module.min.js` — three.js 0.160.0, pinned by sha256 in `assets/vendor/README.md`, MIT (`three.LICENSE`). Replace only with a recorded version and hash; never load three.js from a CDN.
- `index.html` + `assets/main.js` + `assets/style.css` + `assets/presets.json` — older landing page and preset data.

Not this module's scope: any decision logic (the server computes everything), persistence, authentication, notifications.

## Boundaries

- The UI never computes tiers, severities, or eligibility itself; it renders what the API returns.
- `safety.js` must not persist resident answers or guardian topics anywhere (`localStorage`, `sessionStorage`, cookies, query strings, non-local URLs). Answers live only in the in-memory `residents` list for rendering. The topic exists only as a local variable and DOM node inside `showTopicOnce` and disappears when that dialog closes.
- No external network loads from `app.html`, `safety.html` or `home3d.html` (local assets and a data: icon only; only the older `index.html` loads Google Fonts). Do not add other-origin scripts or styles to the safety page.
- Requests to `/api/safety/*` are same-origin `fetch` with `Content-Type: application/json`; the server rejects anything else.

## Invariants

- The safety page has no input for birth date or diagnosis; the three resident questions are exactly "75세 이상인가요?", "혼자 대피할 수 있나요?" (stored inverted as `cannot_self_evacuate`), "인지 저하가 있나요? (보호자만 입력)". Question text comes from the server response (`answers[key].question`).
- `cognitive_decline` is only submittable with `entered_by: guardian`; the UI marks it guardian-only (the server enforces it with 403).
- The consent notice states the answers stay on this device and are used only to decide how strongly to alert.
- Severity is displayed with its Korean label and its sources (표·거주자·모델); a judgment without severity shows "없음" in the 파급도 row and "—" for sources. The lab currently always shows "없음" because the lab path does not run situation logic.
- Error messages shown to the user are the server's one-line Korean `error` string.

## Patterns

- `getJson` / `postJson` helpers wrap `fetch(..., {cache: "no-store"})`; every response is `{ok, ...}` and the UI checks `data.ok` before using fields.
- DOM is built with the `el(tag, cls, text)` helper using `textContent` (never `innerHTML` with server data).
- JSDoc types on functions.

## Tests

- Branch graph (`day-demo.js`, wide view, viewBox 1600×760, pane x 1240–1580, 18-unit node labels and 15-unit chips/pills/pane text so nothing renders under 11px at 1280×800): comfort is two rows (y 220 · 590) of five columns. Exits are dashed arrows into sinks: a top "침묵" lane (y 50) takes row-1 exits (rules, gate1, the score fan's 아무것도 안 하기), a bottom "침묵" lane (y 690) takes the judge exit, and under the gate sit the 보류 sink (dead exit — phone skipped) and the 모아보기 sink (a second route: gate → 모아보기 → phone, that route is the phone's incoming edge and carries the gate's `edge_ko`). Each exit's reason chips sit where it meets its lane (below the bottom lane, so they grow away from the nodes) and are sized to their drawn height. The score node fans out its candidates (pills, joined by stubs labelled with each `final_score`); the selected one continues thick into context and shows score's `edge_ko`. Main-path branches ("다음으로", "바로 폰 알림") get no chip — the lit main edge and its pill say it. Safety/followup/feedback are one row (y 300) with a row lane at y 470: followup exits (not_sent/deadline/error) leave from the 따라가는 알림 node (sent = the lit pane link), feedback `refused` leaves from the feedback node, ladder and phone choices are chips under their node. Exits are only branches with server `exit: true` (every drawn exit carries `data-exit="1"`). When an exit is taken, its arrow, chip and lane/sink light (accent, red for safety) and the main edge after it is off; otherwise exits stay faint dashed. Orphan rule: no node is drawn done/end unless its incoming edge is lit (the trace's first node excepted). `LiotDemo.overlapCheck()` is the layout oracle: it returns `{pairs, outside, clipped}` — intersecting boxes among nodes, chips, pills, fan pills, sinks, lane labels, fan scores, node times and the pane (edge lines excluded), elements outside the viewBox, and text boxes overflowing their own foreignObject; all three must be 0 for every trace kind and the worst cases (rules silence with 9 branches, the longest row-1/row-2 texts, the ~80-character followup Jev text, the judge exit with luna unavailable, a DIGEST trace, a refused tap) at 1280×800 and 390×844 (browser-checked 2026-10-21).
