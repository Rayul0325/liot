### C4.3 규칙 조회 (모델 실행 전에 커밋)

- 코더 두 명(A, B)이 사례 문장만 보고 필드 네 개를 따로 매겼다(`inputs/codeA_output.json`, `codeB_output.json`; 익명 id 는 `inputs/anon_codeA.json`, `anon_codeB.json`). 모델에 들어가는 값은 **코더 A** 것이다(실행 전 고정). 코더 B 는 κ 용이다.

### C4.2 분석 계획
- 다시 쓰기: 라벨·하한·쌍 종류를 보지 않는 에이전트가 쌍 사례 36문장(평온 18·위험 18) 각각에 중립판·놀라게 하는 판을 모두 쓴다(익명 id). 위험 사례에는 중립판, 평온 사례에는 놀라게 하는 판을 등록 팔로 쓰고, 반대 두 칸(위험×놀람, 평온×중립)은 탐색용이다.
- 사실 보존 검사: (1) 사례별 원자 사실 목록(별도 에이전트, `observations_blind.yaml` 정의 + 문장), (2) 검사자 에이전트가 사실 전부 존재·새 사실 없음 확인, (3) 스크립트: 숫자 다중집합 일치, 개체 낱말 대조(추가·누락), 특성 낱말, 길이 ≤ 원문의 1.5배, 시간대 태그 유지, `emit_external` 통과. 하나라도 실패하면 제외. 1차 실패는 다시 쓰기 1회(같은 검사를 다시 통과해야 함) 뒤에 제외 수를 **1차와 최종 둘 다** 팔별로 적는다. 팔별 제외가 20%(18건 중 4건 이상)를 넘으면 판정 불가.
- 유지율 = 원문에서 하한 위로 답한 항목 중 다시 쓴 문장에서도 하한 위로 답한 몫. 판정자별로 계산해 같은 무게로 평균. 바꾸지 않은 문장의 반복 유지율(같은 항목의 rep0 대 rep1)로 나눈 값을 정규화 유지율로 쓴다(결정적 로컬 판정자는 1).
- 평온 사례 증가 = 놀라게 하는 판 올림 비율 − 원문 올림 비율(판정자별, 같은 무게 평균). 붓스트랩은 사례 단위(2,000회).
- 판정(우선순위 순): 제외 > 20% → 판정 불가 / 정규화 유지율 ≥ 0.80 이고 증가 ≥ 10%p → '둘 다' / 유지율 < 0.50 또는 증가 ≥ 10%p → 반증(어휘 쪽) / 유지율 ≥ 0.80 이고 증가 < 5%p → 지지 / 그 외 판정 불가. 점추정으로 판정하고 구간은 함께 적는다.

### C4.3 분석 계획
- 입력: 비주입 45사례(주입 16건은 지표에서 제외라 돌리지 않음). 운영 요약(`ContextBuilder` 문자열) 뒤에 필드를 덧붙인 변형: 필드 A=센서 종류 집합, B=변화율 구간, C=동시 이상 수, D=지속 시간 구간. 팔: 0(운영 그대로) · A · A+B · A+B+C+D(필드 1·2·4개, 고정 순서) + B 단독 · C 단독 · D 단독(필드 하나씩). 같은 순서 누적은 개수와 정체가 섞이므로 단독 팔을 함께 본다.
- 돌아온 몫 = (팔의 올림 − 운영 올림) / (문장 올림 − 운영 올림), 비주입 항목(확인 강도 45 + 파급도 16 = 61), rep0 이 주(rep1 은 보조). **판정자별 분모(문장 − 운영)가 5건 미만이면 그 판정자는 몫을 보고하지 않고 합산에서 뺀다.** 합산 가능한 판정자가 없으면 판정 불가.
- 판정: 주 표기는 C2.5·C3.1 과 같은 **건수 합산 몫**(자격 있는 판정자만). 판정자 같은 무게 평균을 함께 적고, 둘이 0.5 의 반대쪽이면 '읽기에 따라 갈림'. 지지 = 필드 1→2→4개에서 몫이 줄지 않고(0→1→2→4, 0개는 정의상 0) 4개에서 ≥ 0.5. 반증 = 4개에서 < 0.5. 4개에서 ≥ 0.5 지만 단조가 아니면 판정 불가.
- 규칙 대 모델: 같은 필드를 규칙에 넣은 판정과 모델을 (a) 올림 빈도, (b) 초안 라벨 15쌍 ADD-5 놓침·과잉 올림(**초안 라벨 의존**)으로 비교한다. 규칙 기준은 C3.1 과 같다: 놓침 ≤ 모델 중앙값 이고 과잉 올림 ≤ 모델 중앙값 + 1쌍이면 '같거나 낫다'.
- 문장·운영 기준선은 로컬 5모델은 E5 원자료(결정적, 2026-10-19·11-12)를 쓰고, 클라우드 3종은 이번 실행에서 다시 돌린다(같은 시점 비교).

### 주의 (사전 공개)
- 필드 C(동시 이상 수)는 코더 정의상 필드 A(센서 종류 집합) 크기와 거의 같다(둘 다 센서 알림 수). 4필드 곡선에서 C 의 정보 증가분은 작다고 미리 적는다.
- 이 작업자(빌더)는 벤치 문장과 E5 결과 문서를 이미 읽었다. 다시 쓰기·코딩·규칙 매핑은 모두 문장만 보는 별도 에이전트가 했고, 라벨·결과는 그들에게 주지 않았다(에이전트가 저장소의 다른 파일을 열지 않았다는 것은 강제할 수 없고 프롬프트로 금지했다).
- 원자 사실 목록은 다시 쓰기 완료 뒤에 만들었다(검토 지시는 '다시 쓰기 전'). 사실 추출 에이전트가 다시 쓴 문장을 보지 못했고 다시 쓴 쪽도 사실 목록을 보지 않았으므로 독립성은 같지만, 순서 위반으로 적어 둔다.
