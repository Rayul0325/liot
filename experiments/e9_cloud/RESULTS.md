# E9 실제 모델 종단 실행 (H5.4)

## 목적

하루 시뮬레이터를 가짜 모델이 아니라 **실제 모델**(판정 Jev, 비교 luna, 이유 문장·가상 거주자 Haiku, 기억 memgineering)로 돌려서 두 가지를 본다.

1. 파이프라인 전체가 실제 모델에서도 끝까지 돌고, 안전 알림이 늦거나 빠지지 않는가.
2. H5.4: Jev 와 luna 의 원시 답이 얼마나 같은가. 사전 등록 조건(HYPOTHESES v2): "둘 중 하나라도 Gate1 하한을 벗어난 단계에서만 원시 답 일치를 본다. 일치는 정확도가 아니다."

용어: **하한(floor)** 은 결정 규칙표가 정한 '이 정도 이상은 확인을 받아야 한다'는 바닥이다. 모델은 하한을 올릴 수만 있고 내릴 수 없다. **원시 답**은 모델이 4단계 중 가장 높은 확률을 준 칸이다.

## 방법

- 씨앗 1~10, 씨앗마다 3일, `models="cloud"`, 단계 기록(trace) 켬, 연구 기록(research) 켬. 총 30 시뮬레이션 일.
- 키는 기존 코드가 `~/.config/liot/secrets.env` 에서 읽는다(이 실험은 키 값을 읽거나 출력하지 않았다).
- 예산 상한 1.00달러. 시뮬레이터의 추정 비용 합계가 실제로 쓴 것은 **0.0113달러**(표 가격 기준 추정치, 가격 미상 호출 0건). 상한에 닿은 실행 없음.
- 원자료(모델 응답·사건 전체)는 `raw/cloud_runs.jsonl` 에만 있고 git 에 올리지 않는다. 커밋된 `raw/derived.jsonl` 에는 파생 숫자만 있다(호출 수·비용·단계별 시간·이유 작성 성공·하한/Jev/luna 칸 이름). `python -m experiments verify --only e9` 가 이 파일만으로 요약을 다시 계산해 일치를 확인했다.
- 기억 쓰기는 기존 시연과 같이 memgineering `liot-demo` 브레인의 `house-e9-s<씨앗>` 범위에 실제로 기록됐다.
- 기계 부하가 높아(load 14~50) 시간은 **같은 시간대에 번갈아 돈 상대 비교로만** 읽는다.

### 이유 문장·거주자 결정

- 이유 문장: 79건 중 79건을 모델이 썼다(성공률 100%, 씨앗 단위 95% 구간 1.00~1.00). 규칙 문장으로 대체된 경우 0.
- 거주자 결정: 79건 중 79건을 모델이 골랐다(성공률 100%). 성향 표로 대체된 경우 0.
- 폰 알림에서 모델 거주자가 [도움됐어요]를 누른 것: 알림 50건 중 19건, [그만해] 0건(3일이라 짧다).

### H5.4 — Jev 와 luna 의 일치

**판정 불가 — OpenAI 크레딧 소진(429 `credit_balance_exhausted`).** luna 요청 109건이 전부 실패했다(`luna_unavailable` = 109). 확인은 키 값을 찍지 않고 요청 하나의 오류 종류만 읽는 방식으로 했다(`insufficient_quota`). 따라서 일치율 분모가 0이고 사전 등록 조건(일치 비교)을 만족시킬 데이터가 없다. 크레딧이 충전되면 같은 명령으로 다시 돌리면 된다(`derived.jsonl` 과 `cloud_runs.jsonl` 을 지우고 `run` 다시 실행).

luna 와 무관하게 확인된 것(Jev 만):

| 하한 | 판정 단계 | 하한 그대로 | 하한보다 올림 | 하한보다 내림 |
|---|---|---|---|---|
| 잔잔(ambient) | 59 | 59 | 0 | 0 |
| 숨(breath) | 20 | 20 | 0 | 0 |
| 불씨(ember) | 30 | 30 | 0 | 0 |
| 합계 | 109 | 109 | 0 | 0 |

즉 이 3일×10씨앗 장면에서 Jev 의 원시 답은 109단계 모두 하한과 같은 칸이었다. 사전 등록 조건('둘 중 하나라도 하한을 벗어난 단계')을 따르면 **Jev 쪽에서는 해당 단계가 0건**이라, luna 가 살아 있어도 Jev 가 벗어난 단계의 일치는 계산할 수 없었을 것이다(luna 가 혼자 벗어난 단계만 남는다). 이 숫자가 Jev 가 '항상 하한을 따른다'는 일반 결론은 아니다. 이 시뮬레이터 장면(편의 제안 4종과 가스·누수)은 대부분 답이 뻔한 장면이기 때문이다.

## 한계

- luna 가 없어 H5.4 의 핵심 질문(두 모델이 갈리는가)에는 답이 없다.
- 장면이 4종 편의 제안 + 안전 1건으로 좁다. Jev 가 하한을 벗어나는 어려운 장면이 없어서 '벗어남' 자체가 관찰되지 않았다(E5 의 어려운 사례에서 따로 본다).
- 씨앗은 대본의 시각·값만 바꾸므로 실행 사이 호출 수가 거의 같다(60~67). 구간이 좁아 보이는 것은 변동이 작아서이지 표본이 큰 것이 아니다.
- 비용은 시뮬레이터 표 가격 기준 추정이다. 계정 청구서와 대조하지 않았다.
- 실제 모델 응답은 시점에 따라 달라질 수 있어 이 실행은 재현 보장이 없다(원자료를 `raw/cloud_runs.jsonl` 에 보관, 커밋하지 않음).

## 다음 사이클 제안

- **꼬리 가설**: 하한이 낮고 모호한 장면(사람 있는 방의 조명 밝기 큰 변화 등)을 일부러 넣어 Jev 의 '벗어남'이 실제로 생기는 조건을 찾는다.
- **대안 가설**: luna 대신 다른 계열 모델(예: 로컬 모델 jevk5)과 Jev 를 비교해 H5.4 를 크레딧과 무관하게 평가한다.
- 크레딧 충전 후 같은 설계로 luna 를 다시 돌린다(비용 약 0.01달러).

재현: `PYTHONPATH=$PWD .venv/bin/python -m experiments.e9_cloud.run` → `... run --analyze` → `python -m experiments verify --only e9`.
