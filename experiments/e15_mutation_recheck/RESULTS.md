# E15 뮤테이션 재측정 — 빈틈 시험 뒤 점수·부수 처치·단언 부하 (가설 C4.11)

## 먼저 읽을 것

- 용어: **뮤테이션(변이)** = 코드를 일부러 한 곳만 틀리게 바꾼 사본. 테스트가 그 사본에서 실패하면 "잡았다(killed)", 전부 통과하면 "살아남았다(survived)". **뮤테이션 점수** = 잡은 수 / 전체. **부수 처치(collateral)** = 어떤 테스트를 더한 목적과 상관없는 변이까지 더 잡히는 정도. **단언(assert) 부하** = 어떤 코드 줄을 실행하는 테스트들이 가진 `assert` 수의 합. **AUC** = 무작위로 뽑은 '잡힌 변이'가 '살아남은 변이'보다 예측값이 더 클 확률(0.5 = 구별 못함, 1 = 완벽).
- 이 실험은 **사이클 4 지표 적대 검토**(HYPOTHESES.md 커밋 `a73414c`)를 등록 형태로 반영했다. 사이클 4 전체는 탐색이라 주 가설이 없고, 결론은 가설별 판정만 인용한다.
- 핵심 한 줄: **E8 때 15곳을 겨냥한 시험은 그 15곳을 모두 잡았지만(15/15), 겨냥하지 않은 변이는 거의 더 잡지 못했다(핵심 연산자 +0.46%p, 새 연산자 표본 +0.90%p).** 점수가 80.0% → 83.7% 로 오른 것은 대부분 겨냥한 변이가 잡힌 몫이라 구조상 결과다.
- 측정 코드는 `c96392f`(10:47:06)에 결과 전 고정했다. 판정 규칙의 빈 곳을 채운 '읽기'(READING)는 `analyze.py` 머리말에 있다. 실행 중에 바꾼 것은 아래 **사후 변경** 절에 모았다.

## 1. 목적

- C4.11(a): 빈틈 시험 15곳을 더한 뒤 같은 연산자·같은 10개 모듈의 핵심 점수가 오르는가(예측 +5%p 이상, notifier +10%p 이상, 반증은 2%p 미만). 검토 결과 헤드라인 상승은 정의상 오르므로 **구조상 결과**로 표시하고, 등록 시험은 **15곳 밖 변이의 점수(부수 처치)** 두 가지로 바뀌었다: (A) E8 의 같은 변이 중 15곳 아닌 것, (B) E8 에 없던 연산자로 새 씨앗에서 뽑은 표본.
- C4.11(b): "잡힘은 줄 커버리지보다 단언 밀도와 더 강하게 관련된다"(H6.3b). 검토에서 모듈 10개 순위 비교는 커버리지 범위가 97.2~100% 라 편향이 크다고 해서 **변이 단위(핵심 변이 453개, 줄로 묶음)** 로 바꿨다.
- C4.11(c): Gemini 를 두 번째 분류자로 E8 의 생존 변이 분류를 독립 판정(기술 결과).

**(b)의 단서 — 판정을 지지로 두되 증거가 약하다고 읽어야 한다.**
1. 구간 하한이 0.0009 로 사실상 0 에 붙어 있고, 같은 통계량을 다른 부트스트랩 씨앗 20개로 다시 구하면 6개는 0 을 포함한다(`diff_auc_robustness`). 스피어만 버전의 같은 차이는 −0.03 [−0.22, 0.15]로 0 을 포함한다.
2. 차이의 대부분은 '실행 여부'가 449/453 으로 거의 상수라 그쪽 AUC 가 0.5 근처인 데서 온다. 안 닿은 4개는 부하가 정의상 0 이다. 등록한 구조상 결과 조건(실행된 변이만 본 AUC 구간이 0.5 를 포함)은 구간이 0.503 부터라 아슬아슬하게 충족하지 않아 구조상 결과로는 내리지 않았다.
3. **단언 부하의 정보는 '그 줄을 실행하는 테스트 개수'와 구별되지 않는다**: 실행된 변이만에서 AUC 0.626(단언 부하) 대 0.627(테스트 개수). 모듈 안 순위로 바꾸면 구간이 0.5 를 포함한다(0.498). 즉 "단언이 많아서"가 아니라 "더 많은 테스트가 그 줄을 지나서" 잡힌다는 읽기와 가를 수 없다.
4. 모듈 단위 비교에서는 방향이 반대(밀도 ρ −0.22 < 커버리지 ρ +0.24, 구간 넓음)다. 변이 단위 지지와 모듈 단위의 반대 방향이 함께 있다.

## 5. 사후 변경 (결과 전 코드 고정 `c96392f` 이후)

모두 **해당 결과를 해석하기 전에** 정했고, 정한 근거가 결과 값이 아니라 실행 시간·차단이다. 그럼에도 일부는 일부 결과를 본 뒤의 판단이므로 모두 **사후 기준**으로 표시한다.

1. **표본 줄이기(미수행)**: B 표본의 첫 27개 변이(모두 `risk.py`)를 돌려 본 결과 `risk` 의 선택 시험 37개 파일이 부하에서 약 128초 걸려 120초 타임아웃(변이 없는 기준선도 128초)을 넘겼다. 그래서 `risk` 를 B 에서 빼고(0개), 느린 `severity`·`guardrail` 은 10개로 줄였다(`run.py` 의 `FRESH_CAP`; 부분 표본은 분석에서 제외, 계획 293 → 223). 이 때문에 B 는 `risk`·`guardrail`·`severity` 를 거의 대표하지 못한다. 줄이는 규칙은 씨앗 20261202 의 무작위 추출이며 변이 결과로 고른 것이 아니다.
2. **B 의 타임아웃 규칙**: 120초 타임아웃은 양쪽 실행 중 하나에서라도 나면 짝지은 비교에서 빼기로 했다(READING, `analyze.py`). 최종 실행에서 타임아웃은 0건이라 결과에 영향이 없다.
3. **Gemini 로 보낼 코드의 점 표기**: 송신 게이트가 `word.word` 형태를 entity_id 로 막아 모든 코드 조각이 막혔다(95/95). 속성 접근의 점을 `::` 로 바꿔 쓰고 프롬프트에 알렸다(`gemini.render_code`). 게이트가 그래도 막는 것(PII 필드 이름 `geo_precise` 1건)은 더 바꾸지 않고 미송신으로 뒀다. 게이트를 우회하려는 변형이 아니라 서식 변환이지만, 코드 모양이 모델 입력에 영향을 줬을 수 있다.
4. 등록의 빈 곳을 채운 읽기(결과 전, `c96392f`): 구간을 단 판정 규칙, notifier 예측 처리, (b)의 AUC 통계량·구조상 결과 조건. 등록 문구에 AUC 라는 말은 없었으므로 **통계량 선택은 빌더의 읽기**다. 같은 차이를 스피어만으로 구하면 결론이 달라지므로(0 포함) 이 선택이 결과를 좌우한다.

## 6. 한계

- **'처치'가 15곳 시험이 아니라 테스트 9개 추가 + 코드 2곳 변경이다.** A 의 더 잡힘 2개 중 하나는 U5 시험이 잡았다. 15곳 시험만의 부수 효과는 A 의 +0.46%p 보다 작거나 같다.

- B 표본의 문자열 변이(134/223)는 대부분 값이 어디서도 안 쓰이는 문구일 수 있어 '덜 잡힘'이 곧 '안전 빈틈'은 아니다. 동치 판정은 하지 않았다(점수는 동치 제외 전).

- E8 의 옛 값은 E8 때의 기계 부하(load1 평균 47, 최대 108)에서 얻었고 새 값은 평균 50, 최대 60 에서 얻었다. 120초 타임아웃은 두 번 다 900초로 재판정해 부하 영향을 줄였지만 완전히 없애지는 못했다.
- 추가 연산자(292+6개)의 생존 변이에는 전체 테스트 2차를 하지 않았다(미수행). 헤드라인과 판정은 핵심 연산자·타깃 시험 기준이다.
- (b) 단언 수는 정적 계수다: 매개변수 테스트는 1개, 헬퍼 안 assert 는 0 개로 센다. 줄 부하는 테스트 개수와 강하게 겹친다(위 단서 3). 결과 변수는 이진이고 변이는 줄에 묶여 독립이 아니다.
- (c) Gemini 는 함수 조각만 보고 판정했다(호출 구조·죽은 상수 여부·전체 설정 모르고). E8 분류자는 코드 전체와 `CLAUDE.md` 를 읽었다. 변이당 1회라 모델 자체의 변동은 재지 않았다. κ 는 범주 유병률이 치우쳐(빈틈 16%) 낮게 나올 수 있어 AC1 을 곁들였다. 한 분류자가 정답이라는 근거는 없다.
