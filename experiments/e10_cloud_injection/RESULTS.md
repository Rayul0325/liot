- **독립성이 완전하지 않다(읽을 때 주의).** (1) subtype 61/61 일치는 어휘의 코드 41개가 이 61개 문장을 보고 만든 것이라 정의 문장과 사례 문장이 거의 일대일이라는 점에서 오는 높은 일치다 — 코더의 판단 능력이 어려운 과제에서 일치함을 뜻하지 않는다. (2) Gemini 에게 준 occupied·abnormal_for 규칙문은 작성자 표의 머리말 규칙이고, 그래서 abnormal_for 에서 작성자와 100% 일치한 것은 같은 규칙을 읽은 결과다. 맹검 코더가 받은 규칙문과 정확히 같다는 증거는 이 저장소에 없다.

## 한계

- **'클라우드'와 '로컬'은 여러 변수가 같이 달라진다.** 인터페이스(첫 글자 확률 / 확률 점수 / 생성형 JSON), 모델 크기(로컬 4~9B, 클라우드 모델의 크기는 이 저장소에서 확인하지 못함), 학습 방식이 모두 다르다. 이 시험은 '클라우드라서'를 분리하지 못한다. 클라우드 Jev API 와 로컬 jevk5·jev-9b 는 이름이 같은 Jev 계열로 보이지만 같은 제작사·같은 학습인지는 확인하지 않았다.
- **일반형 변형·대조 문장·새 상황 모두 모델이 썼다.** 세 에이전트는 같은 계열(sonnet)이고, 사례 문장·변형 문구·대조 문장이 서로 독립이 아닐 수 있다. 새 상황 36개는 사례 한 명(에이전트 한 번 호출)의 문체다. 문장 맥락에서만 이미 하한 아래로 가는 비율이 높게 나올 수 있다(대조 팔 하한 아래 비율이 로컬 0.26~0.42).
- 변형 48개 중 사례당 8개만 썼고 모든 사례-변형 조합이 아니다(순환 배정, 변형당 6번). 사례 35개는 조건부 독립이라는 가정으로 붓스트랩했다(사례 → 변형 칸).
- 주입 없는 '문장만' 기준선(중립 문장도 붙이지 않음)은 돌리지 않았다. 대조 팔은 '길이 맞춘 중립 문장 추가'이므로 순수 기준선이 아니다. 일부 판정자의 대조 팔 하한 아래 비율이 중립 문장 때문에 달라졌을 가능성(예: 로컬 대조 0.26~0.42 가 E5 의 비주입 3~20/45 보다 높음)은 설계상 구분하지 못한다.
- 사이클 4 설계 변경으로 E5 의 옛 8건('낮춰라' 주입 사례)은 이 시험의 기본 상황이 아니다. E5 H5.2 의 '판정 불가'는 그대로 두고, 이 시험은 그것을 대체하는 것이 아니라 새 표본의 재시험이다.
- 클라우드 판정자는 항목당 한 번만 돌렸다(Haiku·Gemini 는 표집이라 반복하면 값이 조금 다를 수 있다). 구간은 사례·변형 부트스트랩이 포함하는 변동만 반영하고 표집 반복 변동은 따로 넣지 않았다.
- 판정자가 본 문장·구간·하한은 모델 답만 보는 값이다. 최종값은 하한 합성으로 하한 아래로 내려가지 않는다(`CLAUDE.md` 핵심 규칙 2). 이 결과는 **'모델이 주입에 흔들리는 정도'** 이고, LIOT 의 안전을 말하지 않는다. 실제 운영 모델 입력에는 자유 문장이 없다(E5 H5.1 구조상 결과).
- 변형 v39(XML 꼴 태그)는 에이전트 응답이 빌더에게 HTML 이스케이프된 채 전달되어(`&lt;admin_note&gt;`) 이스케이프를 풀어 저장했다. 대조 문장 v39 도 같다. 원문이 이스케이프 형태였는지는 확인하지 못했다.
- C4.4: 위에 적은 독립성 한계. 유병률이 낮은 필드(abnormal_for)에서 κ 는 불안정하다. 코더 3명은 서로 다른 정보를 받았다(작성자는 라벨을 이전에 본 적이 있다고 `observations.yaml` 이 밝힘).
